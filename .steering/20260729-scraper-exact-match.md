# スクレイパー照合の完全一致化と誤検出対策 (2026-07-29)

## 背景

ユーザー要望: `gpt-4o` を登録したときに `gpt-4o-2024-05-13` 等のスナップショットにヒットさせない。

## 実施内容

- [x] `modelMatches` からスナップショット例外ルール(`SNAPSHOT_SUFFIX`)を削除し、トークン完全一致のみに変更
- [x] テーブル最終列(推奨移行先)をモデル名照合の対象から除外(3列以上の行のみ)
- [x] 「No shutdown date announced」等、廃止日未発表の行を除外
- [x] Google の情報源を `?hl=en` 付き deprecations ページのみに変更(changelog はリリース告知混在のため削除、`hl=en` なしだと他言語版が返り日付抽出に失敗する)
- [x] `Accept-Language: en` ヘッダーを追加
- [x] ダッシュボード文言・README を新仕様に合わせて更新
- [x] 実ページに対するスモークテストで全ケース期待通りを確認

## レビュー結果

code-reviewer / security-reviewer を実行し、以下を修正済み(再レビューで合格):

- High: 移行先列のスナップショット名内の日付を廃止日として誤抽出 → ISO 日付の lookbehind を `(?<![\d-])` に変更
- High: 旧仕様で検出済みの古い廃止日が DB に残留 → ページ取得成功かつ3回連続未検出でクリアするヒステリシスを実装(`missCount` カラム追加)
- Medium: `tbd` の部分一致誤爆 → フィルタから削除。`not( yet)?( been)? announced` に拡張
- Medium: 外部フェッチにタイムアウト・サイズ上限なし → 15秒タイムアウト + 5MB 上限
- Low: CRON_SECRET をタイミングセーフ比較に、cron レスポンスのエラー詳細を汎用化、modelName にホワイトリスト検証(`/^[a-z0-9][a-z0-9.-]{0,99}$/i`)、照合クエリの末尾記号トリム

### 未対応の残存事項(Low、許容と判断)

- fetchHtml のサイズ上限はダウンロード後判定(ストリーム読みではない)。公式ページ相手のためタイムアウトで実害を低減
- `pageFetched` の `some()` は複数 URL プロバイダでは不正確になりうる(現状は全プロバイダ1URLのため実害なし)
- 通知メールの snippet は外部ページ由来テキストを無加工掲載(プレーンテキスト送信のため許容)
- 最終列=移行先というヒューリスティックはレイアウト変更に弱い(コメントで前提を明記済み)

## デプロイ時の注意

- `missCount` カラム追加のため `npx prisma db push`(または migrate)が必要
- 旧仕様で検出済みのレコード(例: `gpt-4o` の 2026-10-23)は、新仕様で3日連続未検出となった時点で自動クリアされる
